# 长文本创作：短上下文长内容协议

本能力包解决一个核心矛盾：模型上下文只有 8k-32k，但要产出十万字级的小说、剧本、长文档。原则只有一条：**上下文里永远只放"当前这一步需要的最小信息"，全书状态全部落在文件里。**

## 一、强制流水线（不可跳步）

```
大纲 outline.md → Bible bible.md → 分章草稿 chapters/ch_NN.md → 一致性复检 → 定稿合并
```

每一步的产物必须写成文件，下一步**只读产物文件，不携带对话历史**。禁止"边聊边写"式的连续生成——那样写到第五章上下文就爆了，且前文设定必然漂移。

1. **大纲**：按 `templates/outline.md` 骨架产出。章节表是核心：每章一行，含编号、标题、主旨一句话、出场人物、推进的伏笔。十万字约 30-50 章，每章 2000-4000 字。
2. **Bible**：按 `templates/bible.md` 建立世界观真源。人物卡、地点卡、术语表、时间线、伏笔账本。写作过程中它是唯一权威，任何章节与它冲突以它为准。
3. **文风卡**：按 `templates/style_card.md` 固化叙事人称、句长节奏、用词禁区，附 100 字示例段。所有章节共用同一张文风卡，这是全书口吻统一的保证。
4. **分章草稿**：见下节"分章扇出"。
5. **一致性复检并修复**：按 `templates/consistency_check.md` 逐章勾检。发现的每个问题（人设矛盾、道具/持有人断层、称谓漂移、时间线冲突）必须当场用 edit 修回章节文件，禁止只记录不修复；衔接断层优先改后一章开头做回收。全部修完再定稿合并。

## 二、分章扇出（核心机制）

主任务上下文里**只持有 outline.md 全文 + bible.md 的摘要**（人物名单与一句话简介即可），绝不持有任何章节正文。

每一章用 task 工具派一个子任务去写。子任务提示的组装公式：

```
本章大纲条目（outline.md 中对应那一行及展开）
+ bible.md 中本章出场人物的完整人物卡、涉及地点卡
+ 上一章末尾 300 字（衔接锚，用 shell 截取，不要通读上一章）
+ 文风卡全文
+ 指令：写 2000-4000 字，末段留下一章钩子，产出写入 chapters/ch_NN.md
```

要点：

- **单章 2000-4000 字**。太短则章节数暴涨、衔接成本高；太长则单个子任务上下文吃紧、质量下滑。
- **衔接锚**：取上一章文件末尾 300 字给子任务，让开头自然承接。PowerShell 取法：`(Get-Content chapters/ch_01.md -Raw)[-300..-1] -join ''`；bash：`tail -c 900 chapters/ch_01.md`（中文按 3 字节估算）。
- **章节衔接协议**：每章末段必须留钩子（悬念、未答的问题、将至的事件），下一章开头前两段必须回收该钩子。钩子内容写进大纲对应章的备注，供下一个子任务读取。
- 子任务之间**串行**为主（后章依赖前章末尾）；确无衔接依赖的支线章、番外可并行。若用户要求并行赶工，则各章只拿到大纲级衔接信息，章界断裂风险高——**并行写完后必须执行下述「章界连读」修复，不可跳过**。
- **章界连读（复检必做）**：对每对相邻章节，用 shell 取前章末 200 字 + 后章首 200 字连起来读一遍，专查三类问题：同一事件被两章重演、人物/物品状态跳变、专名前后不一致（人名/父名/地名一字之差）。发现问题改后一章开头做回收，改完重新连读确认。全部章界过完才允许合并定稿。

## 三、一致性锚定

- **写前检索**：子任务动笔前，先 grep bible.md 取本章涉及的人物、地点、设定条目，只读命中段落，不读整个 Bible。
- **新设定即时回填**：章节中新出现的人物、地点、术语、物品，写完本章立即回填 bible.md 对应区块（新增人物卡、术语表加行、伏笔账本登记埋设章）。回填由主任务或子任务末尾完成，不留到"最后统一整理"——那时上下文早已丢失细节。
- **伏笔账本**是防烂尾关键：每条伏笔记录"埋设章 | 计划回收章 | 状态（未回收/已回收）"。定稿前 grep 状态列，"未回收"必须清零或明确弃置。

## 四、上下文纪律（红线）

- **绝不把全书读进上下文**。任何时候都不允许 `cat chapters/*` 式的通读。
- **改稿只 read 目标章节**：用户说"第 12 章某处不对"，只读 ch_12.md（必要时加前后章末尾/开头各 300 字），改完写回。
- **统计字数用 shell 不用通读**：PowerShell `(Get-Content chapters/*.md -Raw | Measure-Object -Character).Characters`；bash `wc -m chapters/*.md`。
- 查"某人物之前说过什么"用 grep 人名扫 chapters/，只读命中行上下文。

## 五、一致性检查清单（复检阶段）

逐章核对（详见 `templates/consistency_check.md`）：

- 人名、称谓前后一致（grep 人名的全部变体）
- 时间线不倒流（对照 bible.md 时间线区块）
- 物品、能力、伤势状态连续（上一章断了的手这一章不能拎重物）
- 伏笔账本全部条目状态明确
- 各章开头是否回收了上一章钩子

## 六、交付形态

```
项目目录/
  outline.md
  bible.md
  style_card.md
  chapters/ch_01.md ... ch_NN.md
  book.md          # 合并产物
```

合并一行命令：

- PowerShell：`Get-Content chapters/ch_*.md -Raw | Set-Content book.md`
- bash：`cat chapters/ch_*.md > book.md`

章节文件名用两位补零（ch_01.md），保证排序正确。交付时给用户 book.md 与分章目录，说明总字数（shell 统计）。
