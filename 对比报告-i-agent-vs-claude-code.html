i-agent 赢在哪

  • 身量：体积 1%、内存 3%，一台机器可并发跑上百个实例，Docker 镜像 15MB 级
  • 国产模型原生：DeepSeek/Kimi/GLM/Qwen/硅基流动/MiniMax 开箱即用，自动容错切换，<think> 流过滤、参数截断消毒等国产模型适配已内建
  • 短上下文生存力：两级压缩 + 分块写 + 子任务扇出，32k 窗口跑完 55KB 游戏数据不崩
  • 领域深度：游戏成品机制完整度反超（存档/数值面板/转场/结局裁定来自模板引擎，不靠模型现写）；生图多供应商内建
  • 确定性兜底：JSON/schema/引用完整性校验器、xlsx 自研写入器，质量不靠模型自觉
  • 零打断：无权限询问，天然适合无人值守批量作业

Claude Code 赢在哪

  • 模型智力：同题快 5-8 倍，一次成功率高，文字质感与长程一致性明显更强——这是模型差距，不是框架差距
  • 通用工程：读改大型代码库、调试、重构仍是它的主场，i-agent 不与之争
  • 生态：MCP、hooks、子代理体系、IDE 集成成熟
  • 代价：238MB/版本、数百 MB 内存、国产模型需转发层、生图需外接、权限交互不适合全自动流水线

坦率结论：在六大目标域（游戏/幻灯/办公/长文/知识库/网页），i-agent + 国产模型经校验器兜底后可用率 9/10，且身量只有对方的 1-3%，适合作为可大规模并发、数据不出境、按量付费極低的办公主力；但速度与文本质感仍逊于顶级模型驱动的 Claude Code。两者的正确关系是分工而非替代：批量流水线归 i-agent，攻坚归 Claude Code。

四、同模型对决：把模型变量拉平之后

为回答「Claude Code 的速度优势是框架还是模型」，三个 agent 全部接同一个 MiniMax API、统一 MiniMax-M3，同一道题（茶馆落地页：响应式/双主题/交错动画/canvas 粒子/零外链）串行实跑。Claude Code 经 ANTHROPIC_BASE_URL 转接其 Anthropic 兼容端点，pi 用其 minimax 供应商配置，i-agent 用 --provider minimax -m MiniMax-M3。

  • i-agent 更快的来源：系统提示只有几百 token（Claude Code 为万级，首轮预填充即差一个量级）、2MB 原生二进制零启动开销、无额外元轮次。
  • pi 的 155 分钟经会话取证：第一个工具调用挂起 2.5 小时（无头模式 stdin/交互问题），其后实际生成仅约 3 分钟——产物质量没问题，但无头可靠性在本环境不达标；i-agent 的 shell 工具超时熔断（默认 120s）正是防这类挂起的。
  • 三份产物同清单全过，尺寸差异主要是内容丰富度（Claude Code 页面板块最多，i-agent 最精简）。

  • pi 是 token 冠军：极简系统提示 + 4 轮一把梭大写入，输入输出都最省——这正是 PRD 选它做循环内核蓝本的原因；代价是无分块防护，遇到更大产物或更小输出窗口就会撞截断。
  • i-agent 请求次数最多（35 次）：分块写（每次 ≤200 行）+ check 校验回路，每轮都重放全量历史所以输入侧合计最大；但 87% 被缓存吸收，新鲜输入 5.5 万与 Claude Code 的 5.2 万几乎持平。
  • 输出侧（通常计价最贵）：pi 1.4 万 < i-agent 2.7 万 < Claude Code 4.8 万——Claude Code 产物最丰满（46KB）也最费；按输出计价 i-agent 约为它的 55%。
  • 速度波动提示：i-agent 补测这轮用时 4.9 分钟（35 轮，比首轮 2.24 分钟多一倍轮次）——M3 的轮次数与 API 时段吞吐都有波动，三家单样本速度应读作「同一量级（2-5 分钟）」，而非稳定名次。

修正后的结论：速度层面「Claude Code 优势」是模型优势，同模型下三家同一量级；token 层面 pi 最省、i-agent 输出成本约为 Claude Code 的一半（分块+校验用请求次数换正确率，靠缓存兜住成本）。选型公式：预算/合规定模型，模型定框架——能用顶级闭源模型时 Claude Code 整体体验最好；用国产模型时，i-agent 在身量、适配（think 过滤、截断防护、供应商容错）与输出成本上占优。
